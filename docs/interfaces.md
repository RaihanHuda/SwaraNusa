# Shared interfaces

Content public/data.json exports an object {provinces:[],entries:[]}. Provinces: {id,name,capital,description,image,imageAlt,sourceUrl,sourceLabel}. Entries: {id,provinceId,category,title,subtitle,summary,image,imageAlt,kind,community,location,paragraphs:[string],facts:[{label,value}],steps:[{title,body}],sourceUrl,sourceLabel,mapQuery?}. category in tari,musik,kerajinan,wisata,kuliner,permainan. kind Pengenalan or Panduan. All image paths /assets/name.ext. Optional photo credit source file docs/sources.md. No fabricated tutorial video/teachers.

API responses JSON, errors {error:message}. GET /api/session => {user:null|{id,name,email,role,isDemo}}. POST /api/auth/register {name,email,password}; login {email,password}; demo {role:user|expert|admin}; logout {}. Auth responses {user}. GET /api/requests => {requests:[]}, GET /api/requests/:id => {request}, POST /api/requests {purpose:informasi|pendamping,provinceId,category,topic,description,city,format,timePreference,consent:true} => {request}. Request {id,userId,userName,purpose,provinceId,category,topic,description,city,format,timePreference,status,createdAt,updatedAt,responses:[],history:[],selectedResponseId}. statuses pending,open,responded,connected,completed,rejected,cancelled. Responses {id,expertId,expertName,message,createdAt,isDemo:true}. History {status,note,createdAt}.

POST /api/requests/:id/action {action:approve|reject|cancel|select|reopen|complete, responseId?,note?}. Admin approves/rejects pending; owner cancels pending/open/responded/connected, selects an existing expert response for pendamping requests in open/responded, reopens connected, completes connected; admin completes informational requests only in responded with at least one saved admin answer. Informational completion without a saved answer returns409 and keeps the request open. Selection always requires a response belonging to that request from an expert. Reopen clears selectedResponseId but preserves responses/history, so an existing response can be selected immediately without waiting for a new response. Pending and closed requests cannot select a response. Experts POST /api/requests/:id/responses {message}; only active approved requests with purpose pendamping (demo expert covers all Sumatra categories; expose demo scope). Admin may respond to informational requests via same endpoint. Notification GET /api/notifications => {notifications:[{id,message,requestId,read,createdAt}]}; POST /api/notifications/read {}. GET /api/experts => {experts:[{id,name,description,categories,provinces,isDemo:true}]} only demo examples. No real phone numbers. Seed demo accounts with no public password; /demo only enabled for localhost-bound preview, document for real deployment.
